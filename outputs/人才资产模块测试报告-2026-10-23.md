## 二、发现的问题

### P1-1 画像列表加载失败误显「还没有画像」空态
**实测复现**：`GET /match/profiles` 连续 2 次超时（>15s），页面显示「还没有画像，点左上角“新建画像”」——把网络错误伪装成「没有数据」，误导用户。
- 位置：`src/pages/Profiles.tsx:101-109`
- 原因：`load()` 的 catch 只 `message.error`（3 秒即逝），`list` 保持 `[]`，Table 照常渲染空态
- 修复建议：增加 `loadError` 状态；失败时渲染「加载失败 + 重试」占位，而非空态

### P1-2 人才库列表失败完全静默
- 位置：`src/pages/TalentList.tsx:254-256`
- 原因：`fetchTalents` 的 catch 仅 `console.error`，用户零感知（无 toast、无错误态、无重试）
- 修复建议：同 P1-1

### P2-1 时间显示 UTC 未转本地（3 处）
- `match.ts` 用 `datetime('now')` 写 **UTC**；`utils/time.ts` 专门提供 `fmtDateTime` 转本地（注释写明此坑），但：
  - `src/pages/Profiles.tsx:356` — `render: (v) => v || "-"` 裸渲染（实测显示「05:48:45」，北京时间实为 13:48）
  - `src/pages/Settings.tsx:868` — `v?.slice(0, 16)`
  - `src/pages/Contracts.tsx:192` — `replace("T"," ").slice(0,16)`
- 修复：统一 `render: (v) => fmtDateTime(v)`（Users/TemplateLibrary/Pipeline 已是正确示范）

### P2-2 匹配结果 UX：0 分「不建议」仍戴「最佳人选」皇冠
- 位置：`src/pages/Match.tsx:796-801`
- 现象：实测软件工程师 vs 医学经理得 0 分、红色「不建议」标签，右上角仍显示 🏆「最佳人选 陈知远 0 分」，自相矛盾
- 修复建议：`ranked[0].verdict === "不建议"` 时不展示皇冠，或文案改「相对最优」

### P2-3（观察项）/match/profiles 偶发 15s 超时——环境性尖峰
- 实测（沙箱 curl，扣 TLS 后）：全量接口 89KB、服务端约 1~1.6s；但 **lite 也出现过 TTFB 7.4s 尖峰**，另有 HTTP:000 代理失败
- D1 数据核对：37 份画像、`jd_raw` 共 21KB、SQL 仅 0.4ms——**代码不慢，是边缘/D1 瞬态尖峰**
- 缓解建议（择一二）：
  1. 列表页不拉 `jd_raw`（省约 25% 体积；编辑时按 id 取全量单条）
  2. 列表接口加 30s Edge Cache（如漏斗接口模式）
  3. 前端失败自动重试一次再进错误态

### P3-1 AI 偶发不给「推荐理由 / 面试建议追问」
- 实测：summary/gaps/risks 齐全，但 `reasons`、`questions` 为空 → 界面显示「推荐理由：AI 未给出」「面试建议追问：无」
- `toStringArray` 已兼容字符串/数组，排除解析丢失——是模型不遵从 prompt
- 修复建议：`reasons` 空时回退 `[summary]`；prompt 加「reasons/questions 必填，不得为空数组」

### P3-2 画像页操作列违反统一约定
- 位置：`src/pages/Profiles.tsx:357-373`
- 问题：`key:"actions"`（应为 `"action"`）；「AI匹配」按钮带 `RobotOutlined` 图标 + 自定义 `ai-btn` 样式（约定：禁图标、`type="link"` 纯文字）
- 建议：改为「AI匹配 / 编辑 / 删除」纯文字链接（AI匹配用非 danger 的 link 即可）

### P3-3 内联硬编码色值（暗色模式隐患）
- `src/pages/Match.tsx:797-799` — `#f59e0b` / `#6b7280` / `#111827`
- `src/pages/Profiles.tsx:354` — `#c0392b` / `#c2c6cc`
- 违反「暗色：文本灰禁内联灰值」约定，暗色背景下不可读
