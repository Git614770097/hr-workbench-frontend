## Bug 修复：套用生成时手动输入框打字焦点被抢（已部署 Version b0089c3e）
- 现象：GenerateDocModal 手动占位符输入框每敲一字，焦点被锁定进富文本编辑器。
- 根因：RichTextEditor 外部 value 同步用 quill.clipboard.dangerouslyPasteHTML，其内部 getSelection(true) 强制聚焦编辑器。
- 修复：改用 quill.clipboard.convert({html}) + setContents(delta, "silent")（不聚焦、不发 text-change）；编辑器本身有焦点时保存并恢复光标位置（min(sel.index, quill.getLength()-1)）。
- 经验：Quill 受控封装的外部值回写一律避免 pasteHTML 系列 API。

### 3. 修掉 ImportModal 一个真实 bug：rowKey 重复
- 原代码 `extractTalent(text, parsed.length, ...)` → `key: String(index)`，index 是**批次内**下标。`setRecords(prev => [...prev, ...parsed])` 会累积，所以分两次各传 2 份文件 → key 得到 `0,1` 和 `0,1`（重复）。
- 后果：`updateRecord`/`removeRecord` 都按 key 匹配 → **编辑一行会同时改两行，删一行会同时删两行**。
- 修复：`keySeq = useRef(0)` + `nextKey()` 生成全局唯一 `row-N`。
- 教训：用「批次内下标」当累积列表的 key 是经典陷阱。

### 4. 后端 /import 补上关键日期（缺口修复）
- `POST /api/talents/import` 的 INSERT 原本只写 18 列，**忽略 birth_date/contract_end/probation_end/resignation_date/notes**；但 `api.importTalents` 的类型签名是 `Partial<Talent>[]`，Talent 里包含这些字段 → 签名承诺多于实现。这也意味着没法批量导入合同到期日来喂风险看板。

### 5. 路由级懒加载（用户选择做）
- App.tsx 用 `React.lazy` 拆 6 个页面，**Login 保持同步加载**（未登录首屏，避免白屏闪烁），Layout 也保持同步（外壳需要立刻渲染）。`<Suspense fallback={pageFallback}>` 包住 Routes。
- **实测收益（首屏必载，含 gzip）**：
  - 改造前：单包 JS 2149 kB / gzip 647.6 kB + CSS 35.0 kB / gzip 5.8 kB ≈ **653 kB**
  - 改造后：674 kB / gzip 213 kB + CSS 10.6 kB / gzip 2.4 kB ≈ **215 kB**（-67%）
  - 82% 的产物（3134 kB）推迟到访问对应路由时才下载；Quill 的 24 kB CSS 也随 TemplateLibrary 分包走了。
- 计算方法：解析 `dist/client/index.html` 直接引用的资源，再递归展开其静态 import（正则 `(?:import|from)\s*["']\.\/xxx\.js["']`），忽略动态 import()。这样得到的才是"首屏真下载量"，只看分包数量会被误导。

## /api JSON 404 兜底 + 部署（Version 006d0e28）
- 问题：worker/index.ts 的 SPA 兜底 `app.all("*")` 会接住**拼错的 /api/* 路径**，返回 HTML+200，前端只能报 JSON 解析失败而非明确 404。修复：兜底前加 `app.all("/api/*", (c) => c.json({ error: "接口不存在" }, 404))`。
